# app/

The browser front end. A static site with no build step and no backend: the CNN
runs in the visitor's browser through ONNX Runtime Web, so a drawing never leaves
their machine.

## Files

| file | what it does |
|---|---|
| `index.html` | markup and controls, loads ORT from a CDN |
| `app.js` | drawing, preprocessing, inference, verdict |
| `style.css` | layout and theme |
| `model.onnx` | not committed, copy from the repo root |
| `labels.json` | not committed, copy from the repo root |

The two model assets are generated by `export.py` in the repo root and are ignored
here so the repository does not carry a second copy. Copy them in before serving:

```
cp ../model.onnx ../labels.json .
python -m http.server 8000
```

An HTTP server is required. Opening `index.html` directly as `file://` fails
because `fetch()` is blocked there, and both the WASM runtime and the model are
fetched.

## How a submission is scored

1. Find the bounding box of the ink on the 320x320 canvas.
2. Stretch that box to 32x32, without preserving aspect ratio.
3. Threshold to pure black and white, ink = 1.
4. If ink covers less than `MIN_INK` of the frame, dilate once.
5. Run the model, softmax the logits, show the top 3.

Steps 1 to 3 exist to match how the training images were made. The dataset crops
each segmented character and resizes it straight to 32x32, so the app has to do
the same. Changing one side without the other is the usual reason an app like this
scores well offline and feels broken in the browser.

Step 4 is the one adjustment the training data does not dictate. Scanned ballpoint
strokes are thicker than a mouse line downsampled to 32x32, and training images
average 21.5% ink coverage, so a thin stroke gets thickened once to land closer to
that distribution.

## Tuning

Both constants are at the top of `app.js`:

- `PEN` (12) is the stroke width in canvas pixels. A drawing that fills the canvas
  shrinks by about 10x, so 12 becomes roughly 1.3 pixels at 32x32, against 2 to 3
  in the training data. Raise it if predictions look poor on large drawings.
- `MIN_INK` (0.12) is the coverage floor that triggers dilation.

## Study mode

The target glyph can be covered while writing, for look, cover, write, check
practice. The transliteration stays visible as the prompt. Cover state is always
released when the verdict appears, since comparing your stroke against the real
glyph is the point of the method. The "start each question covered" preference
persists in `localStorage`.

## Notes

- ORT is loaded from `cdn.jsdelivr.net`, so the first load needs a network
  connection. Vendor `ort.min.js` and the WASM files locally if that matters.
- `labels.json` carries a `display` field that prefixes combining marks with a
  dotted circle (U+25CC). 14 of the 85 classes are marks that do not stand alone
  and render as fragments without it.
- The model expects ink as 1 and background as 0, shaped `[1, 1, 32, 32]`.
